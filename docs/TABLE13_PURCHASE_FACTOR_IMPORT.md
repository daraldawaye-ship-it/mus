# ترحيل عوامل وحدة الشراء من Table13 — 4 نوفمبر 2026

**الجهة:** صيدلية دار الدواء، الشركة `company_id=2` فقط. **البيانات:** 1,959 صفًا في ملف المالك `Table13.xlsx`، والعمودان `المعرف` و`عامل_وحدة_الشراءء`. لا تعتمد المطابقة على أسماء الأصناف أو أرقام أكواد الموقع؛ تُطابق `items.legacy_id` نصيًا.

## آلية الاستيراد
- لا تُنشر صفوف الملف أو أسماء الأصناف ضمن مستودع GitHub العام؛ تصل من الاتصال الخاص إلى مسار الموقع `POST /companies/:companyId/items/purchase-factor-import`، في دفعات قصوى 100 صف.
- الحمولة `{source:"Table13.xlsx", dryRun:true|false, items:[{legacyId:"8252",purchaseFactor:100}]}`. `dryRun` افتراضي `true`. تتطلب عملية الكتابة صلاحية `items.manage` والمصادقة على الشركة الصحيحة؛ يتحقق الخادم من `company_id=2` ومن احتواء اسم الشركة على «دار الدواء».
- يعيد الفحص `received` و`matched` و`alreadyCorrect` و`wouldChange` و`missingLegacyIds`، دون أي تغيير. إذا كان المعرف غير موجود فلا يُنشأ صنف وهمي ولا يحذف شيء. إذا تكرر المعرف في الدفعة أو كان متكررًا في قاعدة الشركة تُرفض الدفعة.
- تُنفَّذ الكتابة بمعاملة واحدة لكل دفعة، مع قفل كروت الأصناف المتطابقة، وتعديل **`purchase_factor` فقط مع `revision=revision+1`** لحفظ شرط `protect_item_master_identity`، و`updated_at`. لكل تعديل حدث تدقيق `item.field.update` بقيمتي قبل/بعد وهوية المستخدم والمصدر.
- إعادة الدفعة نفسها آمنة: إذا تطابقت القيم فلا تعديل ولا رفع مراجعة إضافية ولا سجلات تدقيق إضافية. القيم المقبولة أعداد صحيحة من 1 إلى 1,000,000؛ لا تُمس `order_quantity` أو `reserve_quantity` أو عوامل وحدات البيع أو المخزون أو حركاته أو الفواتير أو أسعار الأصناف.
- تُنفَّذ معاينة **جميع الدفعات** قبل أول كتابة، ثم يُستورد بالتتابع مع إحصاء الحفظ وإعادة فحص القيم. عند انقطاع أو تعارض تعاد فقط الدفعات غير المؤكدة بعد فحص، لا تعاد كتابة قيود مالية.

# الرئيسي — تكامل ChatGPT وصلاحيات المالك والموظفين

## نطاق هذه الدفعة (فرع تطوير فقط، ممنوع النشر التلقائي)

الفرع: `codex/maini-app-permissions-no-deploy-20261022`، مبني على `codex/automatic-app-setup` لأن هذا الفرع يحتوي واجهة الربط الديناميكي `tijara_api_catalog/read/write`. **لا يُدمج هذا الفرع في فرع Railway، ولا تُنشأ له بيئة Railway، إلا بتعليمات نشر مستقلة وصريحة.**

## الأدوار والاتصال

| الحساب | نطاق OAuth | السلطة الفعلية |
| --- | --- | --- |
| مالك المنصة | `tijara.read` أو `tijara.read tijara.write` | العمليات المتاحة له في الموقع؛ كلمة المرور ليست ضمن واجهة ChatGPT |
| المدير العام للشركة | نطاق الموقع نفسه | صلاحيات المدير العام في الشركات التي يديرها فقط |
| الموظف | نطاق الموقع نفسه | شركات عضويته فقط؛ عرض/إضافة/تعديل/ترحيل وفق صلاحيات الخادم |
| المسؤول العام | نطاق الموقع + العام إن سُمح | الإدارة العامة لا تمنح عضوية أو إدارة شركة تلقائيًا |

- يبقى `general_table.read` و`general_table.write` منفصلين ومحجوزين للمالك أو الإدارة العامة.
- يستمر فحص `currentActor` و`companyAccess` وصفحات الموقع والصلاحيات عند **كل طلب**، ولا يُعتد بموافقة OAuth كمنح لصلاحيات شركة.
- لا يتجاوز الاتصال إغلاق الصفحة أو الإيقاف أو الأرشفة أو القيود المحاسبية والتدقيق وإصدارات السجلات.
- ربط الموظف بحسابه: تسجيل الدخول بنفس حسابه إلى صفحة موافقة OAuth؛ لا تستخدم حساب المالك لاتصال موظف.

## تغطية العمليات

- العمليات المتاحة تكتشف ديناميكيًا من `tijara_api_catalog`، وتُنفذ بالمسارات الأصلية للموقع عن طريق `tijara_api_read` و`tijara_api_write`.
- يبدأ تنفيذ أوامر الشركة بالتحقق من `GET /companies` ثم `GET /page-catalog?companyId=...`، وقراءة `actionAccess` قبل الكتابة.
- لا يساوي ظهور عملية في الفهرس امتلاك الصلاحية؛ قد يرجع الخادم 403 أو 404 بحسب الصلاحية وعزل الشركة.
- منعنا تنفيذ SQL حر، وإدارة كلمات المرور عبر MCP، والتغيير المباشر للأدوار من دون صلاحيات.
- العمليات غير المسجلة في API، ومنها المحادثات وبعض عمليات الحذف أو تعديل الفواتير المرحلة، لا يمكن تفعيلها دون عقود وخدمات واختبارات إضافية.

## فحص التعديلات قبل أي نشر

1. على نسخة اختبارية من PostgreSQL: `npm ci`، ثم `npm run check` و`npm run build`.
2. تشغيل `node --import tsx --test tests/chatgpt-scopes.test.ts`.
3. تشغيل `node --import tsx --test --test-name-pattern='(ChatGPT MCP|ChatGPT site access)' tests/api.test.ts`.
4. تأكيد عمل `tijara.read` للموظف، ورفض `POST` عند الاكتفاء بالقراءة، ورفض `GET /users` والجدول العام وعدم تجاوز الشركة.
5. تدقيق ترحيل `990_chatgpt_company_user_scopes.sql` على مخطط اختبار، والتحقق من بقاء رموز النطاقات السابقة صالحة.
6. عند طلب النشر **صراحة فقط**: دمج التغييرات بعناية مع أحدث شيفرة الإنتاج، وإعادة جميع اختبارات الربط والصلاحيات، ثم النشر على Railway والتحقق من الصحة بدون المساس بالبيانات.

## تسمية التطبيق

- يستخدم هذا التكامل الاسم العربي **«الرئيسي»** في تعليمات الربط وشاشة موافقة OAuth واسم خادم MCP.
- اسم البطاقة الذي تعرضه منصة ChatGPT للتحكم بالتطبيق تحدده إعدادات تسجيل App الأصلية؛ لا يكفي تغيير الشيفرة أو skill أو وثائق المستودع لتعديله. يجب تغيير إعداد التسجيل بشكل مستقل عند إتاحة ذلك.

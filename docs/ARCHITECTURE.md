# معمارية الأساس الجديد

تطبيق واحد بوحدات واضحة، مع API مستقلة عن الواجهة وعقود مشتركة وقاعدة PostgreSQL. راجع SPEC.md وDECISIONS.md قبل تغيير حدود العام والشركات.

## توزيع المسؤوليات

| المسار                 | المسؤولية                                                                        |
| ---------------------- | -------------------------------------------------------------------------------- |
| apps/api/src           | Express وتهيئة التطبيق ومسارات API والخدمات وسياسات الوصول والمعاملات            |
| apps/api/migrations    | ترحيلات SQL مرقمة، وتُحفظ الإصدارات المطبقة في schema_migrations                 |
| apps/web/src           | React وRouter وQuery والصفحات ونظام التصميم العربي                               |
| packages/contracts/src | أنواع البيانات ومخططات Zod والأدوار والصلاحيات وتسميات التدقيق والمظهر الافتراضي |
| tests                  | اختبارات HTTP وPostgreSQL والتزامن والألوان والمتصفح                             |
| scripts                | تشغيل PostgreSQL محليًا دون تغيير النظام أو تضمين بيانات الاعتماد                |

TypeScript صارمة للخادم والواجهة والعقود والاختبارات. التطوير يشغّل API وVite في عملية واحدة على المنفذ 3000 افتراضيًا. الإنتاج يقدم dist/public بعد البناء. يجب بدء الأوامر من جذر المشروع؛ تغيير المنفذ يتطلب ضبط APP_ORIGIN كذلك.

## حدود الهوية والصلاحيات

users هو الحساب العام. employees يربط user_id وcompany_id بعلاقة فريدة، مع الدور والتفعيل والصلاحيات وصفة المدير العام. قيود قاعدة البيانات تحمي المالك الوحيد والمراجع والعلاقات المكررة؛ هاتف المستخدم أو الموظف لا يمنح وصولًا.

التحقق داخل الخادم لكل طلب. وصول المالك لا يحتاج موظفًا. المستخدم الآخر يحتاج موظفًا فعالًا في الشركة المحددة. الأدوار العامة لا تتجاوز هذا الشرط. البحث عن حساب لربط موظف محصور في المالك والمدير العام وببريد أو هاتف كامل.

تعديلات الشركات والموظفين والحسابات والتفضيلات تسجل التدقيق في المعاملة نفسها، بعد تطبيع القيم. أقفال السجلات تجعل قرارات الصلاحية وقيم قبل/بعد متسقة أثناء التزامن؛ الأقفال الاستشارية تسلسل إنشاء النطاق والترحيلات. طلب متزامن متعارض يُرفض برسالة قابلة لإعادة المحاولة بدل إكمال تعديل جزئي.

كل استعلام عن موظف أو سجل شركة يجب أن يقيد company_id ويطبق سياسة الوصول. لا تعتمد على إخفاء زر في الواجهة. عند إضافة وحدة جديدة، أضف صلاحياتها ومخططاتها وترحيلها واختبارات العزل والتدقيق. صلاحيات الأساس company.edit وemployees.view وaudit.view، وتضيف المرحلة الثانية accounts.view/manage وcurrencies.view/manage وlocations.view/manage. الإدارة تشمل القراءة في سياسة الوصول دون تعديل الصلاحيات المخزنة لموظف موجود.

## عقد API

البادئة /api. أسماء الحقول camelCase، والمعرفات أعداد صحيحة موجبة بحد PostgreSQL integer، والأوقات ISO UTC. القوائم تعيد `{items,total,page,pageSize}`؛ الشركات تضيف lastCompanyId. الفرز بصيغة `role:desc,name:asc`، مع أسماء أعمدة مسموحة وترتيب ثابت بمعرف السجل. أخطاء الطلبات تعيد `{error:{code,message,fields?}}`.

| المجال        | المسارات                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------- |
| الجلسة        | GET /auth/session؛ POST /auth/register و/auth/login و/auth/logout و/auth/password            |
| الحساب        | PATCH /profile؛ GET /users؛ PATCH /users/:id                                                 |
| التدقيق العام | GET /audit                                                                                   |
| المظهر        | GET /appearance?scope=public أو company:id؛ PATCH /appearance بجسم `{scope,mode,color}`      |
| الشركات       | GET وPOST /companies؛ GET وPATCH /companies/:companyId؛ POST /companies/:companyId/activate  |
| ربط الحساب    | GET /companies/:companyId/users/search?q=exactEmailOrPhone                                   |
| الموظفون      | GET وPOST /companies/:companyId/employees؛ PATCH /companies/:companyId/employees/:employeeId |
| المديرون      | PATCH /companies/:companyId/employees/:employeeId/manager بجسم `{isGeneralManager:boolean}`  |
| تدقيق الشركة  | GET /companies/:companyId/audit                                                              |

أنواع User وCompany وEmployee وCompanyContext وAuditEvent في العقود المشتركة هي المرجع لحقول الاستجابة. الأحداث الحساسة تسجل اللقطة الفعلية before وafter؛ الزيارات المهمة تسجل حدث وصول دون لقطة بيانات مصطنعة. لا توجد API لتعديل السجل.

## الجلسات والتشغيل

كلمات المرور مشتقة بـscrypt وملح عشوائي. رموز الجلسات عشوائية، وتحفظ مشتقاتها فقط في قاعدة البيانات. ملفات تعريف الارتباط HttpOnly وSameSite، ومع Secure في الإنتاج. التعديلات تتطلب JSON ومصدرًا مطابقًا لـAPP_ORIGIN ورمز CSRF عند وجود جلسة. لا تعتمد الحماية على رؤوس proxy غير الموثوقة.

الإنتاج يحتاج DATABASE_URL صريحًا ومصدر HTTPS موثوقًا في APP_ORIGIN؛ عند غيابه على Render يستعمل RENDER_EXTERNAL_URL من إعدادات الخدمة، دون الاعتماد على رأس طلب العميل. المصدر لا يقبل مسارًا أو بيانات دخول أو استعلامًا. الإعداد المحلي يستعمل socket خاصًا، وليس قاعدة إنتاج منشورة. DATABASE_SCHEMA الافتراضي public؛ الاختبارات تختار نطاقًا عشوائيًا منفصلًا وتحذفه بعد التشغيل. لا مالك أو كلمة مرور افتراضية، ولا ترقية تلقائية لأول مسجل؛ owner:create إجراء مستقل موثق في README.

Dockerfile يفصل بناء الواجهة وتثبيت اعتماديات الإنتاج عن الحاوية النهائية، التي تعمل كمستخدم node وتقدم API وdist/public معًا. PostgreSQL مستقلة ودائمة، وTLS عند بوابة الاستضافة. دليل النشر في DEPLOYMENT.md؛ تجهيز الصورة والـBlueprint لا يثبت نجاح نشر عام.

## الواجهة والحالة المتأخرة

الصفحات العامة: الرئيسية والدخول والتسجيل والحساب والمستخدمون والسجل. صفحات الشركات: القائمة ثم النظرة العامة والموظفون والبيانات والسجل، وتضيف المرحلة الثانية الحسابات والعملات وأسعار الصرف والفروع والمعارض والمخازن. الروابط قابلة للتحديث والرجوع والتقدم، ويظل العام نقطة الدخول الافتراضية. شاشات المرحلة الثانية تُحمّل عند فتحها، وتبقى تنسيقاتها ومكوناتها مشتركة.

مفاتيح الاستعلام تتضمن المستخدم والنطاق والمعرفات والفلاتر. تُلغى طلبات القراءة عند تغير نطاقها، وتُفحص صلاحية استجابات التعديلات قبل تحديث الواجهة. تسجيل الخروج يلغي الاستعلامات ويمسح ذاكرتها؛ وجهة الخروج للعام محفوظة مع انتهاء الجلسة في تحديث حالة واحد حتى يلتزم بها Router، ثم تُزال. بذلك لا تنافس حماية الصفحة القديمة وجهة الخروج.

المظهر مستقل للمستخدم وللعام ولكل شركة. التحميل والحفظ مرتبطان بإصدار التعديل، ولا يحفظ زر المظهر قيمًا افتراضية أثناء تحميل التفضيل. الخادم والواجهة يشتركان في DEFAULT_APPEARANCE. الألوان مشتقة بحسب السطح الفعلي في الفاتح والمعتم.

styles.css هو مصدر تنسيق المكونات، وtheme.tsx مصدر اشتقاق الألوان. متغيرات ارتفاع الحقول والصفوف وحشو الكروت وظلالها مركزية؛ ui.tsx يحتوي المكونات المشتركة. الجداول تستخدم صفحات وفرزًا وبحثًا من الخادم وتحديدًا بمعرف السجل؛ بياناتها ليست نسخة كاملة محملة ثم مخفية في المتصفح.

## حدود البيانات الأساسية

الترحيل 002_master_data.sql يضيف الحسابات والروابط النظامية والعملات والإعداد المالي وأسعار الصرف والفروع والمواقع. لكل مرجع خاص بشركة قيد أجنبي مركب بمعرف الشركة؛ لا يكفي أن يكون معرف السجل موجودًا في شركة أخرى. الخدمات تعيد التحقق من المستخدم والعضوية داخل معاملة التعديل، وتُقفل الشركة لتسلسل الترقيم والتهيئة والتعديل والتدقيق. الحذف النهائي غير متاح؛ يحفظ التفعيل والإيقاف هوية السجل وتاريخه.

أكواد الحسابات نصوص من عشرة أرقام؛ تستخدم الزيادة التلقائية BigInt ثم تعيد النص بطوله. السعر نص عشري موجب مضبوط، يُخزن NUMERIC(28,12) ويعاد نصًا دون تحويل إلى Number. تحفظ لحظة السريان بصيغة UTC والمصدر اليدوي؛ السعر غير الموجود يعاد null، والأساسية قيمتها التعريفية 1. تاريخ السعر لا يعاد تفسيره عند تغيير العملة الأساسية؛ التغيير ممنوع بعد تسجيل تاريخ أسعار.

يُنشئ الفرع معرضًا في المعاملة نفسها. إيقاف الفرع يمنع استخدام مواقعه دون تغيير علم التفعيل الخاص بكل موقع؛ إتاحته الفعلية هي فعالية الموقع والفرع معًا. هذه بيانات هيكلية، وليست كميات مخزون أو حركات مالية. العقود والمسارات والقواعد التفصيلية في PHASE_2.md.

تضيف المرحلة الثالثة القيود والسندات والأرصدة وكشف الحساب وفق PHASE_3_ACCOUNTING.md. الفواتير وحركات المخزون والدليل العام والدردشة خارج التنفيذ الحالي. تُراجع تفاصيل الكسور والتحويل والتقريب قبل إنشاء جداولها، ولا تستخدم floating point للكميات أو المبالغ المالية المستقبلية. REQUESTS_REVIEW.md يربط الطلبات المرفقة بالتنفيذ القائم والخطة المقبلة؛ لا يثبت تنفيذ مكونات الأداء أو الوحدات المقترحة لمجرد ذكرها.

## المرحلة المحاسبية الثالثة

الترحيل 005_accounting.sql يضيف المستندات المالية وأسطرها ومراجع الشركة والعكس، وخاصية تحديد الحساب النقدي/البنكي. المسارات في routes-finance.ts والعقود في finance.ts؛ صلاحيات القراءة وإدارة المسودات والترحيل مستقلة. المبالغ NUMERIC(28,6) ونصوص دقيقة، والتحويل والتقريب بـBigInt، مع لقطة سعر الصرف عند الترحيل. الرصيد مشتق من السطور المرحلة بما فيها الأصل المعكوس وقيد عكسه، وكشف الحساب يحسب افتتاحي الفترة والحركة والختامي. إصدارات المسودة ومفاتيح عدم التكرار والمعاملات والتدقيق تحمي التزامن؛ لا إنشاء جداول مخزون في هذه المرحلة.

# ترتيب أصناف البحث في فواتير المبيعات والمشتريات — 1 نوفمبر 2026

- القائمة تعرض 20 نتيجة لكل صفحة بدل 10، مع «السابق» و«التالي» والتمرير داخل النافذة.
- بعد أولوية التطابق التام مع الرمز أو الباركود، يرتب الخادم تنازليًا بحسب صافي الكمية المباعة خلال الشهر المتحرك + الكمية المخزنية القابلة للبيع، بوحدة الصنف الأصغر.
- صافي الكمية المباعة = البيع ناقص مرتجعات البيع، من فواتير البيع المرحلة والأولية المحفوظة معًا. تبدأ فترة الشهر بتاريخ عدن ناقص شهر زائد يوم.
- المتوفر المستخدم في الترتيب = stock_showroom + stock_warehouse، دون مخازن المرتجعات. لا يظهر عمود إضافي للمجموع؛ تظل أعمدة الاسم والرصيد وسعر البيع كما هي.
- ترحيل 173 يضيف net_sale_quantity إلى item_sale_rankings وstaged_item_sale_rankings ويعبئ القيم للتواريخ الجاهزة ويحدثها عند تغيّر الملخصات اليومية. لا يوجد جمع لفواتير أو ملخصات يومية داخل طلب البحث، ولا تعديل للأرصدة أو القيود أو المستندات.
- مسار commerce-options يضيف خيار sort=saleQuantityPlusStock:desc. عند عدم وجود إذن للمبيعات أو للمخزون لا تُكشف البيانات المحجوبة ولا تدخل في حساب الترتيب. البحث النصي المفهرس وأولوية المطابقة الكاملة يبقيان كما هما.
- لحالة عدم الاتصال: مسار item-sale-ranks يرسل رقمًا مضروبًا في 1,000,000 لحفظ دقة الكسور وترتيب الأصناف المحفوظة في الجهاز مرة يوميًا. ترسل الأولويات لجميع الأصناف وليس للأصناف المباعة فقط، حتى لو كانت مبيعات الصنف صفرًا ومخزونه موجبًا؛ تبقى إحصاءات «مرات البيع» مستقلة لبقية المكونات.
- النسخة المحفوظة محليًا لقطة يومية؛ قد يتغير الرصيد منذ آخر مزامنة، بينما يتوفر الترتيب المباشر عند الاتصال.

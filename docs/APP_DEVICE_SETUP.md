# إعداد التطبيق والإشعارات — 2026-10-21

تظهر خطوات إعداد الجهاز أعلى الصفحة تلقائيًا للزائر قبل التسجيل وبعد الدخول، دون البحث في قائمة أو كرت إعدادات. تلتقط الواجهة `beforeinstallprompt` قبل تركيب React، وتعرض زر التثبيت عندما يتيحه المتصفح. عند غياب الحدث تبقى تعليمات التثبيت ظاهرة حسب الجهاز، بما فيها Android وFirefox وiPhone/iPad والمتصفحات المدمجة في التطبيقات، مع نسخ الرابط للمتصفح الخارجي. تهيأ خدمة العامل للتثبيت دون تخزين API أو معلومات الحسابات.

لا ينفذ طلب التثبيت الأصلي إلا بعد ضغطة الموظف. قبول الطلب لا يثبت اكتمال التثبيت؛ تأكيد `appinstalled` أو تشغيل التطبيق بوضع مستقل يخفي خطوة التثبيت. لا نحفظ علامة محلية دائمة قد تخفي الإرشاد بعد حذف التطبيق. لا تتيح جميع المتصفحات معرفة أن نسخة أخرى مثبتة خارج الصفحة؛ عند فتح الرابط بالمتصفح قد يستمر الإرشاد، ويطلب فتح أيقونة التطبيق إن كانت موجودة.

بعد الدخول تظهر خطوة إشعارات الجهاز تلقائيًا حتى اكتمال اشتراك Push وحفظه بالخادم. لا يوجد سؤال داخلي «هل تريد؟» أو خيار إيقاف يخفي الطلب. زر التفعيل يستدعي إذن النظام مباشرة من الضغطة، والموافقة الممنوحة سابقًا تعيد ربط اشتراك الجهاز تلقائيًا. حالات المنع وعدم الدعم والخطأ وعدم تهيئة الخادم ظاهرة وقابلة للفهم؛ لا تُعامل كنجاح. في iOS يحتاج Push تطبيقًا مضافًا للشاشة الرئيسية وتشغيله من الأيقونة. لا يمكن تجاوز رفض الإذن أو تشغيل الصوت واللافتات وموافقة الهاتف برمجيًا، وتظهر تعليمات الإعدادات عند الحاجة.

هذا الإعداد لا يمنح صلاحيات صفحات أو بيانات، ولا يفعّل قوالب تنبيهات غير مطورة، ولا يغير المستلمين أو إعدادات الشركات. تبقى خيارات العمل الداخلية الافتراضية وآلية إرسال الخادم الحالية. التحقق يقتصر على TypeScript والبناء وفحوص تثبيت وإشعارات الجهاز المستهدفة؛ لا يحتاج بيانات تجربة في الإنتاج.

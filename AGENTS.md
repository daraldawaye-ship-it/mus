# Tijara — rebuilt foundation

Read docs/SPEC.md, docs/DECISIONS.md, docs/ARCHITECTURE.md and docs/PHASE_2.md before changes. Read docs/REQUESTS_REVIEW.md when planning later modules; the full new user attachment is preserved in docs/reference/05_FUTURE_REQUESTS_RAW.txt. Its historical dialogue and technical proposals are review material, not blanket authorization or proof of implementation. Current user decisions override the archived original references.
Use this existing isolated checkout; do not create worktrees unless explicitly requested.
Public identity is independent of company employees. Only platform owner creates companies and appoints/removes multiple general managers. Active employees confer scoped access; public roles and phone matches never confer membership. Protect active general managers from public-admin archival unless owner authorizes it.
Use PostgreSQL and transactional mutations with normalized before/after audit values. Passwords and sessions never enter audit output. Use strict TypeScript for API, UI, shared contracts and tests.
Master data is company-scoped through composite foreign keys. Account codes remain 10-digit strings; automatic ranges use BigInt. FX rates are positive exact decimal strings stored as NUMERIC(28,12), with effective UTC dates and manual sources; never invent missing rates or use floating point. New master manage permissions include reading without widening existing employees automatically. Do not add journals, balances or stock movements during phase 2.
Use the single design-system stylesheet and shared components; compact inputs 32px / desktop rows 34px, font 14px; mobile 38px. RTL, keyboard, dark mode, contrast and per-user/per-scope appearance are required. Scope async state and cache keys correctly; preserve multi-sort priority and URL navigation.
Validation: npm run check, npm test, npm run test:browser. Never claim unrun validation or public deployment. No public deployment without explicit user instruction. Never commit runtime database or credentials.

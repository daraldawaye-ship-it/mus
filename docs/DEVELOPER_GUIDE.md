## 6. قاعدة PostgreSQL وترحيلات البنية

البيانات في PostgreSQL مستقلة عن حاوية الويب. عند إنشاء التطبيق تستخدم createDatabase في apps/api/src/db.ts ملف DATABASE_URL من أسرار البيئة وDATABASE_SCHEMA الافتراضي public. ترحيلات SQL مرتبة رقميًا في apps/api/migrations وتُسجل في schema_migrations داخل عملية مقفلة بمعرف النطاق. أضف ملف ترحيل جديدًا بدل تعديل ملف سبق تطبيقه. ضع فهارس للقراءات الشائعة وقيود FK وCHECK الملائمة، ولا تحذف أو تعيد بناء بيانات المستخدم للتغلب على خطأ في schema.

## 7. الاتصال الآمن بقاعدة البيانات

استعمل قيمة DATABASE_URL المعتمدة من أسرار Render المرتبطة بقاعدة PostgreSQL الداخلية في المنطقة نفسها؛ لا تضع الرابط في Git أو الوثائق العامة. الاتصال المباشر بقاعدة الإنتاج لإجراء تغييرات بيانات ليس بديلًا عن واجهات التطبيق المصرح بها. عند قراءة أو تعديل البيانات عبر اتصال الرئيسي المعتمد استخدم سجل عمليات API، واقرأ العقد ومعرف السجل ومراجعة التزامن. لا توسع وصول القاعدة عبر الشبكة العامة لتسهيل التطوير.

## 8. فحص البيئة والبناء والاختبارات

جذر المستودع يحتوي package.json وpackage-lock.json وtsconfig.json وDockerfile. استخدم Node 24 كما في Dockerfile. فحص الأنواع: npm run check؛ بناء الواجهة: npm run build؛ الاختبارات: npm test. توجد اختبارات متصفح متخصصة في tests/ مع أوامر package.json. Dockerfile يستخدم npm ci ثم check ثم build؛ فشل البناء يمنع نشر تحديث سليم. راجع سجلات البناء أو اختبارات المسار المعدل لا تُعلن نجاح اختبار لم يُشغّل.

## 9. الجلسات والمصادقة وحماية التعديل

يبدأ الربط في apps/api/src/app.ts. loadSession يفحص جلسة المستخدم، وmutationSecurity يتحقق من Origin ورمز CSRF للعمليات المعدلة. واجهات OAuth وMCP لها فحوص منفصلة ولا يجوز تمريرها حول حماية المتصفح. تستخدم الواجهة دالة api في apps/web/src/api.tsx وتضيف اعتماد الجلسة وCSRF تلقائيًا. في واجهات الاتصال الجديدة لا تطبع محتوى الرموز أو كلمات السر في السجلات. لا تمنح إنشاء حساب عام حق الوصول إلى كل شركة.

## 10. عزل الشركة والأدوار والصلاحيات

الهوية العامة للمستخدم ليست عضوية شركة. يدقق companyAccess في apps/api/src/policies/access.ts في سجل الشركة والموظف وصلاحياته، والمالك فقط له سلطات محددة. صفحة الدليل ليست مصدرًا كافيًا للإذن؛ يجب تطبيق التحقق في route نفسه. تعريفات الصفحات في packages/contracts/src/pages.ts، ويعكس services/pages.ts وroutes-pages.ts قواعد الإتاحة والمنح. يجب التمييز بين view وcreate وedit وpost وreverse وprint. ابدأ بأقل إذن وامنع القراءة المتقاطعة بين الشركات.

## 11. واجهات API وعقود الاتصال

## 12. الدليل والمجموعات والشروح

# أولويات مهام القضايا

صفحة `/legal-cases` تعرض لوحة جميع المهام المصرح بها، وتستخدم قائمة مهام
كل قضية الفرز نفسه. هذا الاستخدام مستقل عن الجدول العام.

- غير المنجزة قبل المنجزة، ثم الأولوية من 1 (الأكثر استعجالًا) إلى 10.
- دون اختيار يدوي، تُحسب الأولوية عند القراءة من نص المهمة، عناوين القضايا
  المرتبطة، موعد المهمة وأقرب جلسة مسجلة. الكلمات والقواعد في
  `apps/api/src/legal-task-priority.ts`؛ لا تُستنتج مواعيد قانونية غير مسجلة.
- عند تساوي الأولوية يُستخدم أقرب موعد، ثم `sort_order` كترتيب ثانوي، ثم المعرف.
- للمالك تحديد أولوية مهمة واحدة وسببها، أو اختيار التقييم التلقائي مجددًا.
  `task_priority = NULL` يعني التقييم التلقائي. فتح المحرر وحده لا يحوّله إلى يدوي.
- حفظ الأولوية مستقل عن حفظ نص المهمة وترتيب بقية المهام. يتطلب آخر `revision`،
  ويقفل السجل ويسجل قبل/بعد في معاملة واحدة. التعديل القديم يرجع 409.
- تتحقق القراءة من الوصول لكل القضايا المرتبطة؛ الربط بقضية غير مصرح بها
  يمنع ظهور المهمة ومعطيات أولويتها. التعديل اليدوي للمالك فقط.
- تتحدث القائمتان كل دقيقة وعقب حفظ التغييرات. لا تُحذف المهام القديمة
  من الترتيب باقتطاع أحدث 1000 مهمة قبل حساب الأولوية.

عقد الاتصال: `GET /legal/tasks` و`PUT /legal/tasks/:id/priority`، مع
`{priority: 1..10 أو null, revision, reason?}`. العقد مسجل في كتالوج MCP.
حقل `sort_order` الفيزيائي ليس حقل طلب لهذه العملية.

الفحص المركز: `npx tsx --test tests/legal-cases.test.ts tests/legal-task-priority.test.ts`
مع `DATABASE_URL` لقاعدة محلية، ثم `npm run check` و`npm run test:browser:legal-tasks`.
اختبار المتصفح يستخدم مخطط قاعدة بيانات مؤقتًا وهويات وهمية، ويفحص الحفظ
والعودة للتلقائي وثبات بيانات المهام الأخرى وعرض الكمبيوتر والجوال.

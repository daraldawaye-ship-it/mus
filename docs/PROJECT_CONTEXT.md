## تنفيذ التعديلات والنشر

1. استخدم هذا checkout الموجود وتحقق من فرع Render وحالة الخدمة قبل التغيير.
2. طبّق التعديل مع حفظ قواعد الدقة المالية والصلاحيات وتاريخ البيانات.
3. شغّل الفحوص المناسبة، ثم ارفع إلى فرع Render المذكور أعلاه.
4. النشر التلقائي للخدمة متوقف؛ شغّل نشرًا يدويًا بالأداة عند الحاجة وتابع حتى
   `live`، ثم تحقق من HTTP health والسلوك المعني. وجود commit لا يثبت النشر.
5. قد تعمل مزامنة Blueprint بصورة مستقلة عن نشر الخدمة التلقائي. راجع
   `render.yaml` قبل تعديل موارد مدفوعة، ولا تضف تكلفة دون موافقة المستخدم.
6. لا ترفع أسرارًا أو نسخ قواعد بيانات إلى Git. اعتمد الاتصال الداخلي بقاعدة
   Render، واجعل الوصول الخارجي مغلقًا بعد انتهاء النقل.

## دليل النقل والتوافق

راجع `docs/RENDER_MIGRATION.md`. سجل التشغيل النهائي هو `20261023_final1`
في `_alraesy_migration.runs`. أثبت السجل تطابق محتويات الجداول والتسلسلات
وتعريفات قاعدة البيانات قبل تشغيل التطبيق. النسخة المضغوطة محفوظة داخل
`_alraesy_migration.dump_chunks`، وليست ملفًا في Git أو قرص التطبيق المؤقت.

تحققت الخدمة من HTTP الداخلي والخارجي: health والواجهة وOAuth metadata
تعمل، وواجهات البيانات الخاصة ترفض الطلب غير المسجل. لم تُعدّل كلمات مرور
المستخدمين. يتطلب اختلاف الدومين تسجيل دخول جديدًا وإعادة موافقة إشعارات المتصفح
وربط ChatGPT بالمضيف الجديد. مفاتيح VAPID منفصلة عن نسخة البيانات؛ لا تدّع عمل
Web Push إن كانت الخدمة تسجل أنه غير مهيأ.
ضُبط زوج VAPID جديد في إعدادات Render بعد النقل، دون تخزينه في Git.
طلب المستخدم تكرار طلب الإشعارات عند كل فتح/تحديث للموقع ولو بقي الحساب مسجلًا.
يطلب Bootstrap مرة عند أول تفاعل حقيقي في الزيارة، دون علامة sessionStorage
تمنع الزيارة التالية. يظهر تذكير الحظر كل زيارة؛ لا يمكن تجاوز حظر المتصفح.

# إحصاءات الحسابات — المرحلة الرابعة: الحركات والفترات

تاريخ التنفيذ: 2026-10-17. تعتمد هذه الدفعة على المرحلة الثالثة وطلب المراجعة118، وتضيف الترحيل088. تشمل أعداد الحركات، آخر العمليات وتواريخها ومبالغها، وإجماليات البيع والشراء والقبض والصرف. تبقى قيمة الأصناف المرتبطة بالحساب وواجهة الجدول والكرت للدفعات التالية. لا نشر أو تغيير بيانات إنتاج في هذه الدفعة.

## مصدر كل عائلة

| العائلة | النسبة للحساب | قاعدة العدد والمبلغ |
|---|---|---|
| النشاط العام | اتحاد المورد والطرف المالي وحسابات قيود الفاتورة؛ أو حسابات المستند المالي المستقل | الفاتورة مرة واحدة لكل حساب بدل قيودها الثلاثة؛ المستند المالي الآخر مرة واحدة للحساب، حتى إن تكرر في سطوره |
| البيع | الطرف المالي لفاتورة البيع | كل فاتورة مرحلة مرة، وصافي مبلغها الموقع بما فيه المرتجع |
| الشراء | مورد الفاتورة الفعلي فقط | كل فاتورة مرحلة مرة، وصافي مبلغها الموقع؛ لا تنسب إلى الصندوق أو مورد كرت الصنف |
| الشراء النقدي | المورد نفسه عند ثبوت كون الطرف المالي صندوقًا أو بنكًا | جزء من المشتريات؛ لا يجمع معها لاستخراج إجمالي الشراء، وليس سند صرف |
| الصرف والقبض | كل حساب يظهر في سطور السند مرة واحدة | الأصل موجب في تاريخه؛ عكسه حدث مستقل سالب في تاريخ العكس، ولو كان نوع قيد العكس journal |

الفاتورة الصفرية بلا قيد تظل نشاطًا لطرفها المعروف وموردها. تدمج حسابات الفاتورة والقيود قبل العد، وتشمل الروابط الرئيسية والتكلفة والفروق. قيود اليومية والجرد والمحفظة غير المرتبطة بفواتير تبقى أحداثًا مالية مستقلة؛ لا تنشأ أحداث إضافية من HTTP أو إعادة UUID.

تخزن المبالغ والأعداد الدقيقة كنصوص عند حدود API. مجاميع الفترات بالعملة الأساسية المحفوظة وقت الترحيل؛ آخر عملية تحمل مبلغها الأصلي والأساسي وعملتيهما من المستند نفسه. لا تحويل بسعر صرف اليوم ولا جمع للعملات الأصلية المختلفة.

## الفترات وآخر عملية

| المفتاح | الحد الأول والحد الأخير شاملان |
|---|---|
| `oneMonth` | تاريخ العرض ناقص شهر تقويمي زائد يوم، حتى تاريخ العرض |
| `fourMonths` | تاريخ العرض ناقص أربعة أشهر تقويمية زائد يوم، حتى تاريخ العرض |
| `currentMonth` | أول الشهر حتى تاريخ العرض |
| `previousMonth` | الشهر السابق كاملًا |
| `twoMonthsAgo` | الشهر الذي يسبق السابق كاملًا |
| `last30Days` | تاريخ العرض ناقص29 يومًا حتى تاريخ العرض |
| `last7Days` | تاريخ العرض ناقص6 أيام حتى تاريخ العرض |
| `currentWeek` | آخر سبت حتى تاريخ العرض |

الحدود تعود صراحة في الاستجابة. التاريخ الافتراضي يوم Asia/Aden كما المرحلة الثالثة. التاريخ المختار يحكم كل الفترات، وتستبعد المسودات والتواريخ المستقبلية من الأعداد والمراجع.

آخر بيع أو شراء هو أحدث فاتورة مرحلة تحتوي سطرًا موجبًا؛ لا يستبدله المردود الخالص. قد تكون الفاتورة المختلطة ذات صافي سالب أو صفر. آخر قبض أو صرف سند أصلي لم يقع عكسه حتى تاريخ العرض؛ العكس المؤرخ لاحقًا لا يسقطه من تقرير أقدم. الترتيب بتاريخ المستند ثم معرّفه، وفي الحركة العامة يسبق المعرّف فاصل نوع المصدر الثابت. لا يستنتج وقت داخل اليوم من المعرّفات.

## التغطية وتصنيف النقدي

يحفظ مشغل الترحيل لقطة `counterparty_cash_snapshot` من الحساب المالي الحالي للفواتير الجديدة. لا يعيد كتابة الفواتير المرحلة القديمة. يمكن إثبات تصنيف القديمة من قيدها الرئيسي الذي مس الطرف المالي، لأن تاريخ هذا الحساب يمنع تغيير تصنيفه بعد الترحيل. تبقى القديمة الصفرية التي تفتقد الدليل مجهولة التصنيف.

يرجع `purchase.quality` عدد المشتريات مجهولة التصنيف النقدي وتعارض مورد مردود مرتبط، ضمن أربعة أشهر للحساب الحالي. كما يرجع عدد فواتير الشركة مجهولة المورد في النافذة نفسها باسم واضح ذي نطاق شركة؛ لا ينسبها إلى هذا الحساب ولا يخمن موردًا لها.

عند وجود تصنيف نقدي مجهول يعاد `cashPurchasesFourMonthsBase=null`؛ ويبقى الجزء المعروف في `knownCashPurchasesFourMonthsBase` مع عدد الحالات المجهولة. عدم وجود بيانات سابقة لا يثبت اكتمال التاريخ؛ تستمر علامة `recorded_history_only`.

## التخزين والتحديث والصلاحيات

يبني `refresh_account_activity_statistics` التجميع اليومي للحساب المطلوب تحت قفل الشركة، ويضبط جاهزية النشاط والتجارة. لا تعبئة تاريخية واسعة أثناء الترحيل ولا سجل آخر عملية أجنبي يعرقل الصيانة. قراءة آخر المستندات تستعمل المصدر المقيد بالحساب والعائلات المأذونة.

ترحيل الفاتورة أو حذفها يبطل جاهزية النشاط والتجارة لكل حساب مرتبط، بما فيه المورد النقدي الذي لا يظهر في الدفتر. لا ترفع هذه الكتابات إصدار مصدر الرصيد إن لم تمس دفتر الحساب؛ تبقى عروض الاعتماد مستقرة ولا تكشف تغير نشاط تجاري محجوب. محفزات المرحلة الثالثة تبطل الأجزاء عند تغيير القيود، وجيل إعادة ضبط الحركات يمنع إعادة استخدام تجميع سابق. كتابة cache أو إعادة قراءته لا ترفع إصدار المصدر ولا تولد متابعة أو اعتمادًا.

يبقى المسار `GET /accounts/:id/statistics` بصلاحيات الرصيد السابقة. تضاف `operations` بعائلات مستقلة: المبيعات والفاتورة للبيع، والمشتريات والفاتورة للشراء، وصفحة السند والمستند المالي للصرف والقبض. كل فحص يحترم العضوية الحالية والمنع الصريح والأعلام العامة والمحلية والأبوية. العائلة المحجوبة تعاد null دون عدد أو مرجع أو جودة تغطية. عدد وآخر الحركات العامان غير متاحين عند حجب أي مصدر، ولا يعرض مجموع جزئي بعنوان كامل. تحجب metadata النشاط أو التجارة إذا كانت تكشف عائلة غير مأذونة، وتبقى الأرصدة المتاحة قابلة للقراءة.

كشف فحص إعادة ضبط الفواتير أن مسار الصيانة السابق يحذف المصادر قبل بعض إسقاطات الأصناف المضافة لاحقًا. تصحح هذه الدفعة ترتيب التنظيف بالشركة: تحذف حقائق/يوميات أسعار الشراء وإسنادات مورد الحركات ويوميات الأصناف والحسابات أولًا، وتفرغ مرجع آخر عملية جرد، ثم تحذف المصادر وتعيد اشتقاق الإحصاءات وعدادات الجرد. لا تتغير معاينة الصيانة أو تأكيدها أو بصمتها أو تاريخها البشري، ولا يعطل أي قيد أو مشغل. هذا إصلاح للمسار المصرح به، ولا ينفذ إعادة ضبط على الإنتاج.

## التحقق

الفحوص تستخدم قاعدة اختبار محلية صريحة وschema عشوائيًا، ولا ترث `DATABASE_URL` العام. يشمل الاختبار المصادر الفعلية والحدود والتصحيحات ومنع الازدواج وإعادة UUID والحجب وإبطال cache وعزل الشركات. اختبار ترقية مستقل يثبت الفرق بين تصنيف القديم والجديد، دون تغيير فواتير مرحلة أو تعطيل حمايتها.

نجح التشغيل المحلي المشترك بتوقيت Asia/Aden: 17/17 حالة بلا تخطي (7 للحركات والفترات، حالة ترقية، 8 للأرصدة والإجراءات، وحالة أساس التخزين). نجحت أيضًا حالتان قائمتان للصيانة تشملان الأذونات والبصمة والتراجع عند فشل التدقيق وإعادة UUID، وثلاث حالات تجارة قائمة للترحيل والمختلط والتراجع الذري. نجح `npm run check` و`npm run build`. لا اختبارات متصفح محلية في هذه الدفعة لعدم تغيير الواجهة.

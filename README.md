# تجارة — منصة الشركات والمحاسبة والأصناف والمخزون

دفعة المخزون التشغيلي تضيف إعدادات الحسابات والأرصدة حسب الموقع والدفعة، وحركات الأصناف، والمناقلات والجرد مع قيد محاسبي ذري. داخل الشركة افتح **إعدادات المخزون** وحدد حسابات المخزون والمبيعات والتكلفة والفائض والعجز، ثم **المناقلات والجرد** لتسجيل رصيد فعلي أو نقل كميات بين المواقع. واجهتا **أرصدة المخزون** و**حركات المخزون** تعرضان الكميات الدقيقة ومصادرها. المخزون السالب ممنوع في هذه الدفعة، وعوامل الوحدات ثابتة بعد بدء الحركات. تفاصيل الفواتير والدفعة التالية في [PHASE_5_COMMERCE.md](docs/PHASE_5_COMMERCE.md).

القراءة تحتاج inventory.view، وإعداد الحسابات inventory.manage، والمناقلات inventory.post؛ الجرد يحتاج inventory.post وfinance.post معًا. المالك والمدير العام يحصلان عليها، أما الموظف فتمنح له صراحة. الحسابات المخزنية الخمسة لا تغير بعد بدء الحركات دون ترحيل تصحيحي مستقل. تكلفة زيادة الجرد تخص الوحدة المختارة بالعملة الأساسية.

حساب عام مستقل ومساحات شركات وموظفون وصلاحيات، مع دليل حسابات وعملات وأسعار صرف وفروع ومعارض ومخازن، وقيود يومية وسندات قبض وصرف وأرصدة وكشف حساب، وأصناف ووكلاء ووحدات ثلاثية بأسعار مستقلة وتحويل دقيق. المواصفات الحالية في [docs/SPEC.md](docs/SPEC.md)، والمعمارية في [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)، ومعايير التحقق في [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md). عقد المرحلة الثانية في [docs/PHASE_2.md](docs/PHASE_2.md)، وعقد المرحلة الثالثة في [docs/PHASE_3_ACCOUNTING.md](docs/PHASE_3_ACCOUNTING.md)، وعقد الأصناف والوحدات في [docs/PHASE_4_ITEMS.md](docs/PHASE_4_ITEMS.md)، والطلبات الإضافية المحفوظة للمراجعة في [docs/REQUESTS_REVIEW.md](docs/REQUESTS_REVIEW.md).

## التشغيل المحلي

بيئة التحقق الحالية: Debian13، Node24.19.0، PostgreSQL17.11، Chromium المثبت في `/usr/bin/chromium`.

```sh
cd /workspace/mus
npm ci --cache /workspace/.npm
npm run db:start
npm run dev
```

منفذ التطبيق الافتراضي 3000. عند تغييره اضبط PORT وAPP_ORIGIN معًا؛ مثال محلي: `PORT=3001 APP_ORIGIN=http://localhost:3001 npm run dev`. يتحقق الخادم من مصدر طلبات التعديل؛ افتح التطبيق بالمصدر نفسه الذي ضبطته.

PostgreSQL تعمل على Unix socket خاص تحت `/workspace/.tools/postgresql/socket`؛ لا تستمع على منفذ TCP. بياناتها تحت `/workspace/.tools/postgresql/data`، خارج checkout. أمر db:start قابل للتكرار، ولا يمسح البيانات. عند غياب الأدوات ينزل المثبت حزم Debian الرسمية مع الحفاظ على التحقق من التوقيعات والشهادات. المثبت المحلي مخصص لبيئة Debian 13 الحالية.
يمكن استعمال خدمة PostgreSQL أخرى عبر DATABASE_URL. لا تضف بيانات اعتمادها إلى Git.

```sh
npm run check
npm test
npm run test:browser
npm run test:browser:finance
npm run test:browser:items
```

فحص الأنواع يشمل API والواجهة والعقود والاختبارات. الاختبارات تستعمل نطاقات PostgreSQL منفصلة، وتحذفها بعد انتهاء التشغيل، ولا تُنشئ مستخدمين في بيانات التطبيق. test:browser يبني الواجهة ويختبرها عبر Chromium؛ يمكن تغيير مساره بمتغير CHROMIUM_PATH.

اختبارات الأصناف تثبت التحويل الدقيق إلى `1/12` باكت ومبالغ وكميات أكبر من 2^53، والأسعار المستقلة ودقة العملة، والترقيم وعدم تكرار الإنشاء والإصدارات والتزامن والتدقيق الذري وعزل الشركات وسحب الصلاحية أثناء انتظار القفل. تتضمن 65 حالة حفظ دقيق لنسب الوحدات. تحقق المتصفح من وكيل خارج أول 100 سجل، وفقد إقرار عملية حفظ حدثت فعليًا وإعادة نفس الطلب دون كرت إضافي، وحراسة التنقل والتعارض والأرشفة والمرجع المتوقف، والاستجابة المتأخرة والهاتف وRTL والمعتم. مراجعة صور الهاتف والكمبيوتر أكدت بقاء التمرير الأفقي داخل جدول الوحدات.

نتائج Docker التالية تخص صورة المرحلة الثالثة؛ لم يعاد بناء صورة محلية للمرحلة الرابعة. تشغيل الترحيل السادس مثبت بقاعدة PostgreSQL فعلية عبر اختبارات API والمتصفح.

شملت اختبارات المحاسبة مبالغ أكبر من دقة Number، قواعد دقة العملات، الصرف المؤرخ والتقريب، عدم أثر المسودة، إصدارات التعديل، اتجاه القبض والصرف، العكس بعد إيقاف الحساب/العملة، التزامن ومنع التكرار، وفشل التدقيق والتراجع الكامل. تحقق حد اليوم لسعر الصرف نجح أيضًا بتوقيت Asia/Aden. ترتيب كشف اليوم نفسه يبقى صحيحًا حتى بعد إعادة إدخال أسطر مسودة أقدم.

اختبارات الواجهة شملت فقد تأكيد حفظ مستند موجود فعليًا ثم إعادة الطلب نفسه دون تكرار، حفظ مسودة غير متوازنة ورفض ترحيلها، حماية التعديلات عند التنقل والرجوع، صلاحية العرض فقط، الهاتف والمعتم والطباعة، واستجابات الشركات المتأخرة. أُصلح التجاوز الأفقي في الهاتف وارتفاع أزرار الشريط، وتستهدف اختيارات المعرض الفرع الصحيح بعد إضافة المعرض الرئيسي. تجهيز اختبارات المتصفح يستعمل جلسات HTTP حقيقية مع جلسات منفصلة لاختبارات الخروج؛ لم تُضعف حدود الدخول في التطبيق.

الصورة النهائية تعمل كمستخدم node وباعتماديات إنتاج فقط؛ لا Vite ولا سر شهادة البناء في وقت التشغيل. استثناء الثقة محلي فقط لحل SELF_SIGNED_CERT_IN_CHAIN في وكيل شبكة هذه البيئة؛ لا تعطيل للتحقق من الشهادات ولا تغيير للملف المنشور. تحذيرات حجم الحزمة وتعليقات Zod لا تمنع البناء ولم تُخفَ.

حُذفت نطاقات الاختبار والحاويات المؤقتة. هذه الفحوص لا تكتب إلى قاعدة الإنتاج. أصبح رابط HTTPS الموجود يعيد الصحة بنجاح؛ التحقق من وصول إصدار المحاسبة نفسه يظل منفصلًا عن نجاح الاختبارات ورفع Git.

## الملكية والنشر

لا كلمة مرور أو مالك افتراضي. التسجيل العام يمنح نوع عضو فقط. لإنشاء مالك المنصة شغّل داخل طرفية تفاعلية:

```sh
npm run owner:create
```

سيطلب الاسم والبريد وكلمة المرور مع إخفاء إدخالها وتأكيدها. الحد الأدنى لكلمة المرور 12 حرفًا. يُسمح بمالك واحد، ويُرفض الأمر إذا كان موجودًا. للتشغيل الآلي تُحقن OWNER_EMAIL وOWNER_NAME وOWNER_PASSWORD عبر مدير الأسرار، ويمكن توفير OWNER_DISPLAY_NAME وOWNER_PHONE. لا ترسل كلمات المرور في المحادثة أو تحفظها في Git أو تكتبها ضمن أمر يبقى في سجل الطرفية.

المالك وحده ينشئ الشركات ويعيّن المديرين العامين. لا تمنح صلاحيات الموقع العام عضوية شركة.

تشغيل الإنتاج يتطلب بناء الواجهة وDATABASE_URL صريحًا لقاعدة PostgreSQL الخاصة بالنشر، ومصدر HTTPS موثوقًا في APP_ORIGIN. على Render يمكن أخذ المصدر من RENDER_EXTERNAL_URL الذي توفره المنصة عند غياب APP_ORIGIN؛ النطاق المخصص يحتاج APP_ORIGIN بقيمته النهائية. بعد حقن هذه المتغيرات:

```sh
npm run build
npm start
```

التطبيق يقدم الملفات المبنية وAPI من المنفذ نفسه. تُنهى TLS عند بوابة النشر التي تختارها؛ الجلسات في الإنتاج تستخدم ملفات تعريف ارتباط Secure. لا يثق التطبيق تلقائيًا برؤوس proxy. الترحيلات تطبق عند بدء التشغيل وتُحفظ إصداراتها في schema_migrations. DATABASE_SCHEMA اختياري، وقيمته الافتراضية public. لا تعدّل ترحيلًا سبق تطبيقه؛ أضف ترحيلًا جديدًا عند تغيير البيانات.

أذن المستخدم بتعديل الموقع ونشره على Railway الموجودة، والفرع المرتبط بالخدمة هو codex/deploy-phase2. خطوات الربط والبناء واعتماد حساب المالك والتحديث في [دليل النشر](docs/DEPLOYMENT.md). رفع الفرع يبدأ النشر التلقائي وفق إعداد الخدمة؛ النجاح العام يحتاج تحقق الرابط والسجلات. لا توجد بيانات اعتماد Railway متاحة حاليًا لهذه البيئة، لذلك يعتمد بدء النشر على الربط التلقائي القائم. عاد فحص الرابط العام للعمل؛ يلزم التحقق من ملفات الإصدار الجديد بعد الرفع.

## نطاق هذه الدفعة

الحساب العام والدخول والملف الشخصي والصلاحيات العامة؛ الشركات والموظفون والأدوار والمديرون؛ سجل تدقيق عام/شركة؛ نظام تصميم عربي RTL مدمج، وجداول مشتركة، ومظهر مستقل لكل مستخدم ونطاق.

الشركة تملك الآن دليل مجموعات وحسابات حركية بأكواد ثابتة من عشرة أرقام، مع ترقيم تلقائي اختياري وربط حسابات نظامية؛ عملات وإعداد الأساسية وأسعار صرف يدوية مؤرخة بمصدر؛ وفروعًا تنشئ معرضًا تلقائيًا ومخازن متعددة. الريال اليمني YER افتراضي التهيئة المؤكد، والأسعار نصوص دقيقة دون قيم مصطنعة. توجد صلاحيات مستقلة للقراءة والإدارة، وكل تعديل وتدقيقه معاملة واحدة. لا تُمنح الصلاحيات الجديدة تلقائيًا لموظف سابق.

المرحلة الثالثة تضيف قيود اليومية وسندات القبض والصرف ومسودات بإصدارات وترحيلًا وعكسًا موثقًا، مع مبالغ دقيقة وأسعار صرف تاريخية وأرصدة وكشف حساب وطباعة. صلاحيات القراءة وإدارة المسودات والترحيل منفصلة؛ لا تعديل صامت للمستند المرحل، ولا أثر للمسودة على الرصيد. يجب تعريف الحساب النقدي/البنكي بخاصية cashOrBank قبل استخدامه في سند.

المرحلة الرابعة أ تضيف كروت الأصناف ووكلائها ورمزًا تلقائيًا ثابتًا من ثمانية أرقام والباركود والاسم الإنجليزي ومفاتيح البحث. لكل مستوى وحدة سعر مستقل وعملة صريحة؛ حفظ الكرت بإصدار ومفتاح منع تكرار. الأعداد الكبيرة والكسور في معاينة التحويل دقيقة دون تقريب كسر دوري. الحقول تشمل الشراء والطلب والانتهاء والأرشفة؛ لا ينشأ رصيد أو حركة مخزون من معاينة الكرت. التفاصيل في [PHASE_4_ITEMS.md](docs/PHASE_4_ITEMS.md).

ابدأ من الشركة ← وكلاء الأصناف ثم الأصناف ← صنف جديد. اختر عملة الأسعار من العملات المعرفة، وأدخل أسماء الوحدات وأعدادها وأسعارها. للموظف امنح items.view أو items.manage؛ المالك والمدير العام يحصلان عليها تلقائيًا.

الفواتير وحركات المخزون والمذكرات والنقاط والدليل العام والدردشة وتطبيقات الهاتف مراحل لاحقة. المواصفات الأصلية محفوظة في docs/reference مع إعطاء الأولوية للقرارات الحالية. يتضمن [سجل مراجعة الطلبات](docs/REQUESTS_REVIEW.md) 50 بطاقة في سبع مجموعات و12 مجموعة قرارات، مع إحالات للملف المرفق الكامل؛ يعاد النظر فيها عند تثبيت مرحلة الأصناف والوحدات والمخزون، دون اعتبار جميع الاقتراحات التقنية متطلبات فورية.

القرارات التي تفسر الفصل بين العام والشركات محفوظة في [docs/DECISIONS.md](docs/DECISIONS.md). قواعد المحاسبة في PHASE_3_ACCOUNTING.md وقواعد كروت الأصناف والتحويل في PHASE_4_ITEMS.md؛ بقية حركة المخزون والمناقلات والتسويات في المواصفات المرجعية إلى حين تنفيذها.

التنفيذ القديم محفوظ للاسترجاع خارج المستودع في `/workspace/rebuild-archives/mus-before-rebuild.tar.gz`. قاعدة SQLite القديمة مؤرشفة معه، ولا تُستخدم في التطبيق الجديد. الأرشيف ليس نسخة من بيانات PostgreSQL الجديدة؛ يلزم إعداد نسخ احتياطي لقاعدة الإنتاج عند اختيار الاستضافة.

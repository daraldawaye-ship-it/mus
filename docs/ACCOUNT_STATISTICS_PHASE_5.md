# إحصاءات الحسابات — المرحلة الخامسة: قيمة الأصناف المنسوبة للحساب

تاريخ التنفيذ: 2026-10-17. تعتمد الدفعة على المرحلة الرابعة وطلب المراجعة119، وتضيف الترحيل079. تنفذ مؤشر «قيمة الأصناف المتوفرة للحساب» وفق توضيح المستخدم: المورد المسجل في كرت الصنف هو أساس النسبة للحساب. لا تضيف كمية مورد مستقلة أو تغير ربط المورد القائم.

## المعادلة والنطاق

قيمة الحساب = مجموع `stock_item_valuations.value_base` للأصناف التي تحمل `items.supplier_account_id` مساويًا لهذا الحساب. الربط بمفتاح الشركة والصنف يضمن مساهمة واحدة لكل صنف؛ لا ربط بصفوف المواقع والدفعات لتجنب تكرار قيمة pool. تشمل القيمة الأصناف غير الفعالة والمواقع المؤرشفة ذات المخزون، وتضم كامل رصيد الصنف في الشركة.

التقييم هو التكلفة الحالية المعتمدة في المخزون، لا أسعار بيع الكرت أو شرائه ولا سعر صرف اليوم. المبالغ الموقعة والأعداد الدقيقة نصوص في API. الصنف بلا pool يساهم بصفر وفق حالة المخزون الحالية؛ والصنف بلا مورد لا ينسب إلى حساب افتراضي.

تقسم القيمة إلى `confirmedValueBase` للأصناف ذات المورد المحدد و`inferredValueBase` للأصناف ذات `supplier_inferred=true`، ومجموعهما `valueBase`. هذا تقسيم لجودة **إسناد المورد**، وليس إثبات ملكية مالية للمخزون أو درجة يقين تكلفته. لا يعاد توزيع فواتير الشراء القديمة أو صور المورد التاريخية عند تغيير كرت الصنف.

النظام الحالي يسمح بالمخزون السالب وفق إعداداته. تحافظ الدفعة على قيمة pool الموقعة دون قصها إلى صفر، وترجع عدد أصناف العجز وقيمتها الموقعة في `negativeStockItemCount/negativeStockValueBase`. قد تكون القيمة صفرًا لعجز ذي كلفة غير معروفة؛ لا يقدم هذا العدد بوصفه كمية متوفرة ولا القيمة بوصفها مقدار نقص موجبًا. تظل سياسة البيع السالب والتقييم المؤقت القائمة مصدر هذه القيم دون تغيير.

## استجابة القراءة

تضاف إلى `GET /companies/:companyId/accounts/:id/statistics`:

| الجزء | المعنى |
|---|---|
| `stockAvailability` | available أو restricted وفق صلاحيات المستخدم الحالية |
| `stock` | لقطة القيمة الحالية أو null عند الحجب |
| `stock.basis` | `current_item_card_supplier` |
| `stock.scope` | `current_transaction_state` |
| `stock.asOfDate/snapshotAt` | تاريخ يوم الاحتساب في Asia/Aden ووقت بناء اللقطة |
| `stock.currency` | العملة الأساسية وكودها ودقتها في اللقطة |
| `stock.valueBase/confirmedValueBase/inferredValueBase` | الإجمالي وتقسيم الإسناد |
| `stock.assignedItemCount/inferredItemCount` | عدد كروت الأصناف المنسوبة، بما فيها صنف رصيده صفر، وجزؤها المستنتج |
| `components.stock` | metadata جاهزية اللقطة أو null عند الحجب |

لقطة المخزون **حالية ومستقلة عن تاريخ تقرير الأرصدة والحركات**: طلب تقرير تاريخي لا يعيد بناء مورد الكرت أو التقييم في ذلك الماضي. تضم الحالة الحالية كل حركة مرحّلة، حتى إن حملت تاريخ مستند مستقبليًا. لذلك ترجع اللقطة نطاقها وتاريخها الخاصين صراحة، ولا تحمل تاريخ التقرير القديم على قيمة المخزون الحالية.

## التحديث والثبات

`refresh_account_stock_statistics(company,account)` يقفل الشركة ثم الحساب والملخص، ويعيد التجميع للحساب المطلوب عند الحاجة. تخطي الاحتساب مشروط بالحالة وإصدار الدفتر وتاريخ اليوم وجيل المصدر ولقطة العملة. لا تعبئة واسعة للتاريخ أو احتساب eager أثناء الترحيل.

تغير قيمة pool أو كميته يبطل جاهزية ملخص مورد الكرت الحالي. تغير المورد يبطل القديم والجديد، وتغير وسم الإسناد وحده يبطل التقسيم أيضًا. يشمل ذلك المورد الذي تستنتجه ترحيلات النظام أو تؤكده مشتريات جديدة. لا ترفع تغييرات الكرت أو المخزون وحدها إصدار الدفتر المالي ولا تغير عرض اعتماد رصيد لم يتغير؛ أي أثر مالي حقيقي يبقى تحت خطافات المرحلة الثالثة المعتادة.

إعادة ضبط الحركات المصرح بها تصفر pool ثم تدور جيل المصدر، وتبقي المورد الحالي للكرت وتاريخ المتابعة والاعتماد البشريين. بعد القراءة يعاد بناء القيمة من الحالة الفعلية. كتابة الملخص ليست متابعة أو اعتمادًا ولا تولد أي إجراء بشري.

## الصلاحيات والتحقق

إضافة إلى وصول الحساب وكشفه والإحصاءات، تحتاج قراءة القيمة إلى عرض الأصناف وأرصدة المخزون وحركاته. هذه هي صلاحية الكلفة الحالية في واجهات المخزون القائمة؛ لا تمنح قراءة كرت الحساب قراءة المخزون من نفسها. تتحقق الخدمة من المنح الدقيقة والمنع الصريح والأعلام العامة والمحلية والأبوية قبل تحديث هذا الجزء أو قراءة قيمه. تحجب القيمة وmetadata كليهما عند عدم الإتاحة، بينما يبقى الرصيد المصرح به قابلًا للقراءة.

الفحوص محلية داخل schema عشوائي وبمتغير اختبار خاص دون وراثة `DATABASE_URL` العام. تغطي التجميع بلا تكرار، الدقة والعملات، المورد المباشر والمستنتج، تغيير الكرت، العجز، الأرشفة، الحجب وعزل الشركات والصيانة. الواجهة والجدول المستقل وربط حقل كرت الحساب تبقى الدفعة التالية؛ لم ينشر هذا التغيير أو يطبق على الإنتاج.

نتيجة التشغيل المحلي المشترك: 24/24 حالة ناجحة بتوقيت Asia/Aden، منها سبع حالات جديدة لقيمة المخزون، مع فحوص الأرصدة والحركات والترقية وأساس التخزين السابقة. نجحت حالتا المناقلة والجرد والصيانة القائمتان، ونجح `npm run check` و`npm run build`. راجعت جهة مستقلة المصدر والخطافات والدلالة الزمنية والحجب دون ملاحظات مانعة. لا اختبارات متصفح محلية لعدم تغيير الواجهة.

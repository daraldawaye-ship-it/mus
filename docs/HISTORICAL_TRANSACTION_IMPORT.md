# ترحيل المستندات التاريخية — 2026-10-15

طلب المستخدم ترحيل سندات وفواتير دار الدواء كحركة فعلية في الموقع، بمنشئ Admin وترقيم تلقائي جديد. وافق على اختلاف الترتيب الزمني والأرقام؛ يُثبت تاريخ الترحيل الحالي ويحفظ الرقم والتاريخ والمستخدمون ومعرفات السطور القديمة وبيانات المصدر الأصلية في مرجع الاستيراد ووصف المستند. الأرصدة الافتتاحية ومعالجة الحسابات العشرة غير المطابقة لاحقًا.

مسار المالك `POST /companies/:companyId/transaction-import/batch` يرحل إلى جداول الفواتير والمخزون والدفتر الموجودة وخدماتها نفسها. جدول المصدر فهرس للربط والتدقيق وعدم التكرار، وليس دفتر حركة مستقلًا. الهوية الفريدة شركة+نظام مصدر+نوع+معرف مصدر؛ السند يستخدم معرف الحركة لأن أرقام السندات تتكرر. UUID ثابت للدفعة ومفتاح المستند والبصمة الكاملة تمنع تكرار الطلب أو تغيير المصدر المقبول صامتًا.

تقبل الدفعة حتى100 مستند، مع بقاء حد الفاتورة التاريخية200 سطر والتحقق من كل مستند كما هو. يتحقق المسار من المالك والشركة والصفحات داخل قفل الشركة، ويؤكد UUID المقبول قبل فحص تعطيل الصفحات. كل مستند داخل savepoint مستقل؛ فشل مستند يرجع كل أسطره ومخزونه وقيوده دون منع مستند صحيح في الدفعة. تُفحص قيود قاعدة البيانات المؤجلة داخل savepoint. فشل تدقيق الدفعة يرجع الدفعة كلها. تُحفظ نتيجة الدفعة حتى لا يعيد طلب متأخر إنشاء حركة حُذفت بصيانة مصرح بها لاحقًا.

السياق الداخلي التاريخي فقط يسمح بسعر البيع الصريح بعد الخصم، وبصلاحية غير معروفة حين لم ترد في المصدر، وبحساب مصروف حركي وارد صراحة في المصدر؛ لا يعاد تصنيف الحساب ولا تُخترع صلاحية. القيود العادية على السعر والانتهاء وأنواع الحسابات تبقى كما هي. تظل المراجع الفعالة والعزل والأرصدة والتقييم والتواريخ المحددة صراحة ودقة العملة والقيود المزدوجة إلزامية. لا تمنح المستندات المستوردة نقاط عمل أو عمولات حديثة. الفاتورة التاريخية حتى200 سطر تحفظ كاملة؛ API اليومية تبقى100.

تعني الكمية الأصلية الوحدة الرئيسية. تحول إلى وحدات صحيحة موجودة في الكرت فقط؛ ضجيج تصدير الكسور الدورية يوثق مع النص الأصلي وحد الخطأ الصارم، ولا تقرب كمية حقيقية غير قابلة للتحويل. تؤجل الفاتورة كاملة عند عدم توافق وحداتها أو دقة أسعارها؛ تؤجل المستندات الكاملة المرتبطة بالحسابات غير المطابقة. المبالغ الصفرية لا تنشئ قيودًا مصطنعة.

في السندات المصدرية `معرف_الحساب` هو الصندوق و`معرف_الصندوق` هو الحساب المقابل؛ إشارة المبلغ تحدد القبض أو الصرف الفعلي مع حفظ النوع القديم. تبقى السندات المرتبطة والتحويلات عبر الحساب الوسيط كحركات منفصلة؛ لا تتحول كل حركة منها إلى تحويل نقدي مباشر مكرر. تعرّف الحسابات المستوردة المصنفة أصلًا `cashbox` صراحةً كصناديق عبر API الحسابات، دون تغيير هويتها أو فئتها. تحفظ أرقام الوصول المصدرية في البيانات الأصلية دون تسميتها أرقام وصول مورد حين تكون معرفات ربط.

# دردشة تجارة

طلب المستخدم في 2026-10-18 دردشة بتصميم احترافي وحالتي «تم الاستلام» و«تم العرض»، وأكد دعم التواصل بين مستخدمي تجارة وبين أعضاء الشركة. هذا التنفيذ يضيف محادثات خاصة ثنائية في النطاقين، ببيانات مستقلة وروابط `/chat` و`/companies/:companyId/chat`، وصفحتي الدليل الثابتتين `public.chat` و`company.chat` وإجرائي `view` و`create`.

## الوصول والخصوصية

تعاد مراجعة الحساب الحالي وعضوية الشركة وصلاحية الصفحة والمنع الصريح في الخادم. دخول دردشة الشركة للعضو الفعال أو مالك المنصة وفق قواعد الوصول الحالية؛ بدء رسالة جديدة يحتاج مستلماً متاحاً في النطاق نفسه. الدليل يعرض المعرف والاسم فقط ولا يكشف الهاتف أو البريد أو الصلاحيات.

لا تتيح الإدارة العامة أو ملكية الشركة قراءة محادثة بين شخصين آخرين أو تأكيد استلامها. يستمد الخادم الطرف الأول من جلسة المستخدم، ويحدد الرابط الطرف المقابل فقط. بعد إيقاف الطرف المقابل أو مغادرته الشركة يحتفظ الطرف الحالي المخول بتاريخه؛ العضوية الحالية للمستخدم القارئ وصلاحياته تبقى إلزامية. الحساب المؤرشف أو الموقوف عن المشاركة لا يستخدم الدردشة.

## الرسائل والتأكيدات

- «تم الإرسال»: قبل الخادم الرسالة وحفظها في PostgreSQL.
- «تم الاستلام»: أكد متصفح المستلم استلام معرف الرسالة المحدد، من معاينة قائمة المحادثات أو تحميل الرسائل.
- «تم العرض»: عرض متصفح المستلم الرسالة داخل المحادثة الظاهرة مع تركيز الصفحة، ثم أرسل تأكيداً صريحاً لمعرفها.

التحميل وحده عبر GET لا يكتب تأكيداً. معاينة المحادثة تؤكد الاستلام فقط. مراقب ظهور الرسائل يؤكد المعروض منها، فلا يعني فتح محادثة قراءة كل تاريخها. هذه تأكيدات المتصفح ولا تثبت أن الإنسان قرأ النص أو فهمه.

الخادم يقبل تأكيدات المستلم لرسائل واردة تخص محادثته ونطاقه فقط. يجري فحص جميع المعرفات قبل الكتابة، ويُرفض الطلب المختلط دون تحديث جزئي. أوقات الإرسال والاستلام والعرض من الخادم، تحفظ أول تأكيد ولا تتراجع عند إعادة المحاولة؛ تأكيد العرض يثبت الاستلام أيضاً. النص والطرفان ومعرف طلب الإرسال غير قابلة للتعديل بعد الحفظ. يسجل التدقيق الحدث دون نسخ نص الرسالة إليه.

لكل إرسال UUID يثبت مع الفاعل والمستلم والنص المطبع داخل النطاق العام أو الشركة. إعادة الطلب المطابق تؤكد الرسالة نفسها، بما في ذلك بعد فقد الرد وإعادة تشغيل التطبيق؛ اختلاف الحمولة يعيد 409. التأكيد المطابق يبقى متاحاً بعد تعطيل الصفحة مع إعادة فحص الحساب والعضوية والمنع الصريح، والرسائل الجديدة ترفض. يمكن استخدام UUID نفسه في نطاق مستقل دون ربط بيانات النطاقين.

## الواجهة

الواجهة عربية RTL بنظام التصميم المشترك، بقائمة محادثات وبحث ودليل بدء محادثة وفقاعات رسائل وحالة غير المقروء وسجل قابل للتصفح ومحرر رسالة. في الهاتف تتبادل القائمة والمحادثة المساحة ويظهر زر العودة، مع محرر داخل مساحة العرض. يحترم المظهر الفاتح والمعتم وتفضيل المستخدم المستقل لكل نطاق.

المسودات والرسائل التي لم يتأكد إرسالها تحفظ محلياً بمفتاح المستخدم والنطاق والطرف، مع إعادة الإرسال بنفس UUID والحمولة. لا تحول الواجهة فشل الاتصال إلى نجاح أو استلام أو عرض. تبديل المستخدم أو الشركة يعزل حالة الصفحة وطلبات الشبكة وذاكرة الاستعلامات. تحديث المحادثات دوري أثناء نشاط الصفحة؛ لا توجد خدمة WebSocket أو إشعارات دفع في هذه الدفعة.

## العقود والتحقق

تضيف الهجرة `090_private_chat.sql` المحادثات والرسائل ومؤشرات القراءة وقيود سلامة السجل. العقود المشتركة في `packages/contracts/src/chat.ts`، والعمليات:

- `GET /api/chat/directory` و`GET /api/chat/conversations`.
- `GET /api/chat/conversations/:peerId/messages`.
- `POST /api/chat/conversations/:peerId/messages` مع `clientMessageId` و`text`.
- `POST /api/chat/conversations/:peerId/receipt` مع `deliveredMessageIds` و/أو `readMessageIds`.

تتطلب جميع العمليات `scope=global` أو `scope=company` مع `companyId` للشركة فقط، في الاستعلام للقراءة وفي الجسم للكتابة. طول الرسالة 1–4000 محرف بعد حذف الفراغ المحيط؛ التأكيد حتى 100 معرف في كل قائمة؛ التصفح بمؤشر مربوط بالمستخدم والنطاق والطرف والبحث.

التحقق المطلوب هو `npm run check` و`npm run build` و`npx tsx --test tests/chat.test.ts` و`npm run test:browser:chat`. تختبر الحالات المركزة الخصوصية والمنع الحالي والعضوية، إعادة الإرسال المتزامن والدائمة، تأكيد المعرفات الدقيقة والتوقيت، وفصل النطاقين. اختبار المتصفح يستخدم جلستين حقيقيتين وخادم PostgreSQL للتحقق من الاستلام ثم العرض الظاهر، والهاتف والمظهر. ينشئ كل اختبار مخططاً عشوائياً مستقلاً ويحذفه؛ لا يستخدم بيانات الإنتاج.

يشغل `.github/workflows/chat-ci.yml` هذه الفحوص في PostgreSQL مؤقت مع صور المتصفح وملفات trace كمرفقات. وجود الاختبارات أو إعداد CI ليس إثباتاً لنجاح تشغيلها أو نشرها؛ يسجل التنفيذ الفعلي ونتيجته في تقرير العمل. المجموعات والمرفقات والحذف والتحرير وحظر المستخدمين وإشعارات الدفع لاحقة.

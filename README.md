# تجارة — أساس المنصة والبيانات الأساسية للشركات

حساب عام مستقل ومساحات شركات وموظفون وصلاحيات، مع دليل حسابات وعملات وأسعار صرف وفروع ومعارض ومخازن. المواصفات الحالية في [docs/SPEC.md](docs/SPEC.md)، والمعمارية في [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)، ومعايير التحقق في [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md). عقد المرحلة الثانية في [docs/PHASE_2.md](docs/PHASE_2.md)، والطلبات الإضافية المحفوظة للمراجعة في [docs/REQUESTS_REVIEW.md](docs/REQUESTS_REVIEW.md).

## التشغيل المحلي

بيئة التحقق الحالية: Debian13، Node24.19.0، PostgreSQL17.11، Chromium المثبت في `/usr/bin/chromium`.

```sh
cd /workspace/mus
npm ci --cache /workspace/.npm
npm run db:start
npm run dev
```

منفذ التطبيق الافتراضي 3000. عند تغييره اضبط PORT وAPP_ORIGIN معًا؛ مثال محلي: `PORT=3001 APP_ORIGIN=http://localhost:3001 npm run dev`. يتحقق الخادم من مصدر طلبات التعديل؛ افتح التطبيق بالمصدر نفسه الذي ضبطته.

PostgreSQL تعمل على Unix socket خاص تحت `/workspace/.tools/postgresql/socket`؛ لا تستمع على منفذ TCP. بياناتها تحت `/workspace/.tools/postgresql/data`، خارج checkout. أمر db:start قابل للتكرار، ولا يمسح البيانات. عند غياب الأدوات ينزل المثبت حزم Debian الرسمية مع الحفاظ على التحقق من التوقيعات والشهادات. المثبت المحلي مخصص لبيئة Debian 13 الحالية.
يمكن استعمال خدمة PostgreSQL أخرى عبر DATABASE_URL. لا تضف بيانات اعتمادها إلى Git.

```sh
npm run check
npm test
npm run test:browser
```

فحص الأنواع يشمل API والواجهة والعقود والاختبارات. الاختبارات تستعمل نطاقات PostgreSQL منفصلة، وتحذفها بعد انتهاء التشغيل، ولا تُنشئ مستخدمين في بيانات التطبيق. test:browser يبني الواجهة ويختبرها عبر Chromium؛ يمكن تغيير مساره بمتغير CHROMIUM_PATH.

## التحقق المنفذ

تحقق المرحلة الثانية وإعداد الإنتاج: 2026-10-11، على التنفيذ الجديد وقاعدة PostgreSQL الفعلية. فحوص تثبيت ملف القفل والإنتاج وإنشاء المالك سبق تنفيذها في 2026-10-10؛ لا تعني هذه النتائج نشر الموقع على الإنترنت.

| الفحص                       | النتيجة                                                                  |
| --------------------------- | ------------------------------------------------------------------------ |
| npm ci ثم db:start          | نجح تثبيت ملف القفل وبدء قاعدة البيانات بصورة قابلة للتكرار              |
| npm run check               | نجح فحص TypeScript للخادم والواجهة والعقود والاختبارات                   |
| npm test                    | 40 ناجحًا: 14 للأساس، و15 للبيانات الأساسية، و3 للألوان، و8 لإعداد الإنتاج؛ دون فشل أو تخطي |
| المتصفح بعد بناء الإنتاج    | 15 سيناريو ناجحًا، دون فشل أو أخطاء متصفح                                |
| npm run build               | نجح بناء الإنتاج                                                         |
| بدء التطوير                 | نجحت الصحة والجلسة والصفحة العربية بعد إعادة التشغيل                     |
| بدء الإنتاج محليًا          | نجح تقديم ملفات البناء والرابط المباشر؛ وصول شركة دون جلسة أعاد 401      |
| owner:create في نطاق اختبار | نجح إنشاء مالك واحد ورُفض الإنشاء المكرر                                 |
| صورة Docker للإنتاج         | نجح البناء والتشغيل بمستخدم غير root واعتماديات الإنتاج فقط             |
| فحص الحاوية على PostgreSQL  | نجحت الترحيلات والصفحات وملفات البناء وحماية الجلسة وإنشاء المالك؛ بقيت البيانات والجلسة بعد إعادة التشغيل |

اختبارات التزامن تتحقق من موظف ومالك وحيدين عند الطلبات المتزامنة، وحماية تعيين المدير أثناء أرشفة الحساب، وتسلسل قيم التدقيق عند حفظ المظهر. اختبارات المرحلة الثانية تتحقق من عزل الشركات في HTTP وفي المفاتيح الأجنبية، وصلاحيات القراءة والإدارة وسحب الوصول أثناء انتظار التعديل، والترقيم بعد 999 وعدم تكرار الأكواد، وتهيئة العملات دون تغيير هويات سابقة، وأسعار NUMERIC الدقيقة وتطبيع الوقت، وإتاحة المواقع والتراجع الكامل عند فشل التدقيق. تعديل الاسم وحده لا يعيد تفعيل موظف أو فرع ولا يمحو حقولًا لم تُرسل.

اختبارات المتصفح تقيس ارتفاع الصفوف والحقول وحجم الخط وتباين الألوان، وتختبر الفرز والصفحات والتحديد والمظهر والاستجابات المتأخرة والخروج إلى العام. السيناريوهات الأربعة الجديدة تنشئ وتعدل وتربط بيانات الشاشات الخمس، وتبحث اختيارات تتجاوز أول 100 سجل، وتؤخر الحفظ لكل شاشة أثناء الانتقال إلى شركة أخرى، وتختبر الكثافة في الفاتح والمعتم على الهاتف والكمبيوتر والتمرير بلوحة المفاتيح لآخر رابط جانبي على ارتفاع 768px. المراجعة البصرية المستقلة سجلت سبع لقطات ببيانات معزولة، دون تمدد خارج عرض الهاتف أو أخطاء متصفح.

تظهر رسالة رفض تدقيق متعمد أثناء اختبارات التراجع؛ هذه حالة حقن خطأ للتحقق من عدم حفظ تعديل دون سجله، وليست فشلًا في الاختبار. البناء يصدر تحذيرات غير معيقة من تعليقات حزمة Zod ومن حجم الحزمة الأولية (نحو 517KB، و155KB بعد gzip)؛ لم تُعطّل التحذيرات. الشاشات الجديدة منفصلة في ثلاث حزم تحمل عند فتحها؛ بقية تحسين الأداء ضمن المراجعة المحفوظة، دون ادعاء قياس جاهزية لحمل إنتاج كبير. لم يُختبر نشر خارجي أو بوابة TLS فعلية.

فحص Docker في 2026-10-11 استعمل PostgreSQL الحقيقية في نطاق اختبار منفصل ومنفذ 10000 كما في Blueprint. تحقق من غياب المستخدمين الافتراضيين وVite في الصورة النهائية، وسمات Secure/HttpOnly/SameSite، ورفض المصدر غير الموثوق وطلب الخروج دون CSRF، وبقاء الحسابات والجلسة بعد إعادة تشغيل الحاوية. فحص YAML والروابط بين الموارد نجح محليًا؛ قبول خطط Render والتحقق عبر نطاق HTTPS فعلي يتطلبان حساب الاستضافة.

بيانات التطبيق بقيت خالية من حسابات الاختبار، وحُذفت النطاقات التي أنشأتها فحوص هذه الجلسة بعد انتهائها. يوجد نطاق فحص قديم فارغ باسم api_dev_smoke؛ ليس نطاق التطبيق الفعلي public، ولم يُمس.

## الملكية والنشر

لا كلمة مرور أو مالك افتراضي. التسجيل العام يمنح نوع عضو فقط. لإنشاء مالك المنصة شغّل داخل طرفية تفاعلية:

```sh
npm run owner:create
```

سيطلب الاسم والبريد وكلمة المرور مع إخفاء إدخالها وتأكيدها. الحد الأدنى لكلمة المرور 12 حرفًا. يُسمح بمالك واحد، ويُرفض الأمر إذا كان موجودًا. للتشغيل الآلي تُحقن OWNER_EMAIL وOWNER_NAME وOWNER_PASSWORD عبر مدير الأسرار، ويمكن توفير OWNER_DISPLAY_NAME وOWNER_PHONE. لا ترسل كلمات المرور في المحادثة أو تحفظها في Git أو تكتبها ضمن أمر يبقى في سجل الطرفية.

المالك وحده ينشئ الشركات ويعيّن المديرين العامين. لا تمنح صلاحيات الموقع العام عضوية شركة.

تشغيل الإنتاج يتطلب بناء الواجهة وDATABASE_URL صريحًا لقاعدة PostgreSQL الخاصة بالنشر، ومصدر HTTPS موثوقًا في APP_ORIGIN. على Render يمكن أخذ المصدر من RENDER_EXTERNAL_URL الذي توفره المنصة عند غياب APP_ORIGIN؛ النطاق المخصص يحتاج APP_ORIGIN بقيمته النهائية. بعد حقن هذه المتغيرات:

```sh
npm run build
npm start
```

التطبيق يقدم الملفات المبنية وAPI من المنفذ نفسه. تُنهى TLS عند بوابة النشر التي تختارها؛ الجلسات في الإنتاج تستخدم ملفات تعريف ارتباط Secure. لا يثق التطبيق تلقائيًا برؤوس proxy. الترحيلات تطبق عند بدء التشغيل وتُحفظ إصداراتها في schema_migrations. DATABASE_SCHEMA اختياري، وقيمته الافتراضية public. لا تعدّل ترحيلًا سبق تطبيقه؛ أضف ترحيلًا جديدًا عند تغيير البيانات.

طلب المستخدم نشر النسخة الحالية ثم تطوير بقية المراحل. الاستضافة المقترحة Render بخدمة Docker وPostgreSQL مدارة؛ خطوات الربط والبناء وإنشاء المالك والتحديث في [دليل النشر](docs/DEPLOYMENT.md). تفعيل حساب الاستضافة واعتماد تكلفة موارده مطلوبان لإتمام النشر العام، الذي لم يُتحقق منه بعد.

## نطاق هذه الدفعة

الحساب العام والدخول والملف الشخصي والصلاحيات العامة؛ الشركات والموظفون والأدوار والمديرون؛ سجل تدقيق عام/شركة؛ نظام تصميم عربي RTL مدمج، وجداول مشتركة، ومظهر مستقل لكل مستخدم ونطاق.

الشركة تملك الآن دليل مجموعات وحسابات حركية بأكواد ثابتة من عشرة أرقام، مع ترقيم تلقائي اختياري وربط حسابات نظامية؛ عملات وإعداد الأساسية وأسعار صرف يدوية مؤرخة بمصدر؛ وفروعًا تنشئ معرضًا تلقائيًا ومخازن متعددة. الريال اليمني YER افتراضي التهيئة المؤكد، والأسعار نصوص دقيقة دون قيم مصطنعة. توجد صلاحيات مستقلة للقراءة والإدارة، وكل تعديل وتدقيقه معاملة واحدة. لا تُمنح الصلاحيات الجديدة تلقائيًا لموظف سابق.

الأرصدة والقيود والفواتير وحركات المخزون والمذكرات والنقاط والدليل العام والدردشة وتطبيقات الهاتف مراحل لاحقة. المواصفات الأصلية محفوظة في docs/reference مع إعطاء الأولوية للقرارات الحالية. يتضمن [سجل مراجعة الطلبات](docs/REQUESTS_REVIEW.md) 50 بطاقة في سبع مجموعات و12 مجموعة قرارات، مع إحالات للملف المرفق الكامل؛ يعاد النظر فيها عند تثبيت مرحلة الأصناف والوحدات والمخزون، دون اعتبار جميع الاقتراحات التقنية متطلبات فورية.

القرارات التي تفسر الفصل بين العام والشركات محفوظة في [docs/DECISIONS.md](docs/DECISIONS.md). تفاصيل مراحل المحاسبة والمخزون، بما فيها الوحدات الثلاث والكسور والفروع والمناقلات، ما زالت ضمن المواصفات المرجعية.

التنفيذ القديم محفوظ للاسترجاع خارج المستودع في `/workspace/rebuild-archives/mus-before-rebuild.tar.gz`. قاعدة SQLite القديمة مؤرشفة معه، ولا تُستخدم في التطبيق الجديد. الأرشيف ليس نسخة من بيانات PostgreSQL الجديدة؛ يلزم إعداد نسخ احتياطي لقاعدة الإنتاج عند اختيار الاستضافة.
